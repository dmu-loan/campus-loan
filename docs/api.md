# API 명세

백엔드와 프론트엔드의 약속입니다. API를 추가·변경할 때는 **이 문서를 먼저 수정**하고 둘 다 승인한 뒤 구현합니다.

## 공통 규칙

### 기본 주소

- 모든 API는 `/api`로 시작합니다.
- 관리자 전용 API는 `/api/admin`으로 시작하며 로그인이 필요합니다.
- 로컬 개발 시 프론트엔드(Vite, `5173`)가 `/api` 요청을 백엔드(`8080`)로 프록시합니다.

### 요청·응답 형식

- 본문은 JSON(`Content-Type: application/json`)을 사용합니다.
- 필드 이름은 **camelCase**를 사용합니다. 예: `studentNo`, `dueAt`
- 날짜·시각은 **ISO 8601**, 서울 시간 기준입니다.
  - 날짜: `2026-11-18`
  - 시각: `2026-11-18T17:00:00`
- 목록 응답은 배열을 그대로 반환합니다.

### 에러 응답

```json
{ "message": "사용자에게 보여 줄 안내 문구" }
```

| 상태 코드 | 의미 |
| --- | --- |
| `400` | 입력값 오류, 규칙 위반 (재고 없음, 운영시간 외 등) |
| `401` | 로그인 필요 |
| `403` | 권한 없음, CSRF 토큰 누락 |
| `404` | 대상 없음 |
| `409` | 충돌 (중복 신청, 동시 승인 등) |

프론트엔드는 에러 시 `message`를 그대로 사용자에게 보여 줍니다.

### 인증

- 세션 쿠키 기반 로그인입니다.
- 상태를 바꾸는 요청(`POST`, `PUT`, `PATCH`, `DELETE`)은 CSRF 토큰이 필요합니다.
  - 서버가 `XSRF-TOKEN` 쿠키를 내려주면, 프론트엔드는 같은 값을 `X-XSRF-TOKEN` 헤더에 담아 보냅니다.
- `fetch`를 사용할 때는 `credentials: "include"`를 지정합니다.

### 템플릿

#### `METHOD /api/경로`

설명 한 줄

- 권한: 누구나 / 관리자 / 마스터
- 요청

```json
{}
```

- 응답 `200`

```json
{}
```

- 에러: `400` 언제, `409` 언제
